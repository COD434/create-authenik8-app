# Local security dashboard

Authenik8 Studio is a local, read-only dashboard for applications generated by
`create-authenik8-app`. It turns the source-controlled project manifest, an
offline Doctor report, and the version-aware upgrade plan into one actionable
view.

Run Studio from the generated project:

```bash
npx create-authenik8-app@latest studio
```

Or point it at a project explicitly:

```bash
npx create-authenik8-app@latest studio ./my-app
```

This is the Authenik8 equivalent of invoking Prisma Studio: it runs only when
you request the `studio` command. Generated `dev`, `start`, and production
commands do not import, start, or depend on Studio.

## What it shows

- Local security posture and actionable Doctor findings
- Capabilities declared in `authenik8.json`
- Generated structure, script, manifest, and engine drift
- Current and target generator and `authenik8-core` versions
- Outstanding upgrade actions
- Production readiness as an explicit, separate assessment
- The highest-priority next command

Studio does not use a security score. Failed and warning counts remain visible,
and a passing offline snapshot is never represented as certification.

## Preset compatibility

Studio uses the same snapshot, security, and rendering path for every generated
preset. The capability list adapts to the source-controlled manifest:

| Preset | Additional capability information |
| --- | --- |
| `base` | Optional Prisma/database configuration |
| `auth` | Prisma-backed password identity boundary |
| `auth-oauth` | Prisma plus the selected Google and/or GitHub providers |
| `fullstack` | Workspace API persistence plus selected OAuth providers |

The compatibility suite generates all four presets, runs the real offline
Doctor and upgrade assessment, and renders each result through the Astryx
dashboard. Package-manager and runtime differences remain inputs to the project
contract; they do not create separate Studio implementations.

## Offline security boundary

Studio builds one immutable snapshot when it starts. Doctor runs in offline
mode against `.env.example`, holds synthetic validation values only in memory,
and does not contact Redis, PostgreSQL, OAuth providers, or the generated
application.

Studio reads:

- `authenik8.json`
- Security-significant generated structure and package declarations
- `.env.example` variable names and non-secret example semantics
- Installed package metadata when present

Studio does not read or collect:

- `.env` values
- Passwords or user records
- Access or refresh tokens
- Private signing keys
- Database or Redis contents
- OAuth client secrets
- Analytics or telemetry

The HTTP server binds only to `127.0.0.1`, validates the request `Host`, accepts
only `GET` and `HEAD`, and sends a restrictive Content Security Policy. The
snapshot API is held in memory and is not written to the generated project.

## Production readiness

Studio deliberately displays production readiness as **Not assessed**. A real
assessment can contact configured services and exercise the installed identity
engine, so it remains an explicit command:

```bash
npx create-authenik8-app@latest doctor --production
```

Restart Studio after making changes to build a new offline snapshot. Studio
does not poll files, watch the project, or rerun diagnostics on every browser
request.

## Options

Use another loopback port:

```bash
npx create-authenik8-app@latest studio --port 5559
```

Start without opening a browser:

```bash
npx create-authenik8-app@latest studio --no-open
```

Stop the process with `Ctrl+C`. There is nothing to disconnect or remove:
Studio creates no generated-app scripts, credentials, background service,
project files, or hosted connection.

## Failure behavior

- A missing or invalid `authenik8.json` stops startup with an actionable error.
- A port conflict stops startup instead of choosing a surprising network
  address.
- Missing evidence is shown as failed, skipped, or not assessed; it is never
  converted to a healthy state.
- Browser launch failure does not hide the loopback URL printed in the
  terminal.

Studio is available locally without an account. A future hosted team dashboard
can add shared history and notifications without changing this local execution
boundary.

## Availability and support

Local Studio is a Community feature and requires no Authenik8 account. It
supports the same Node.js versions as the generator:
`^20.19`, `^22.12`, and `>=24`. CI exercises Linux on Node 20, Windows on
Node 22, and macOS on Node 24.

Studio is tested against all four generated presets. Browser assets are
self-contained in the CLI package, so a generated application does not install
React, Astryx, or Studio dependencies.

## Troubleshooting

- **Studio says `authenik8.json` is required:** run it from a current generated
  project or pass that project's directory explicitly.
- **Identity engine is missing:** install the generated application's
  dependencies, then restart Studio.
- **The view is stale:** Studio is point-in-time, not real-time. Stop it and
  rerun the command after project changes.
- **The port is already in use:** pass another loopback port with `--port`.
- **The browser does not open:** use the loopback URL printed in the terminal,
  or start with `--no-open`.
- **Production remains `Not assessed`:** run the displayed
  `doctor --production` command explicitly; Studio never contacts live services.

## Maintainer notes

Snapshot construction performs one pass over Doctor checks and upgrade actions.
For `c` checks and `a` upgrade actions, view-model work is `O(c + a)` with
`O(c + a)` snapshot space. The snapshot is serialized once at startup, so HTTP
requests do not trigger project rescans or nested work.

The browser source lives under `studio-src/` and uses React with the Astryx
component system. `npm run build:studio` type-checks that source and writes the
self-contained browser assets under `studio/` for npm packaging. Authenik8 owns
the small theme layer in `studio-src/styles.css`; its colors intentionally
match the documentation site without coupling Studio to the Docusaurus
application.

The server, snapshot contract, CLI parsing, and presentation source remain
separate modules. The browser has a compile-time type import for the snapshot
contract but no runtime import from the CLI. Contributors can change the
interface without changing diagnostic policy, and generated applications never
receive React, Astryx, or Studio dependencies.

`tests/integration/studio-presets.test.ts` protects the four-preset contract.
`tests/unit/studio-ui.test.ts` checks snapshot rejection, actionable navigation,
semantic structure, and automated axe rules. `npm run test:studio:package`
installs the packed tarball into a disposable consumer, generates a project,
and verifies the packaged server, security headers, assets, and snapshot API.
