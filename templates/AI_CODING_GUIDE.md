# Authenik8 AI Coding Guide

This project was generated by create-authenik8-app. Authenik8 owns identity,
authentication, authorization, sessions, and secrets. Treat it as the backend
authority for any AI-generated frontend or tooling.

## Non-negotiable rules

- Never move authentication, authorization, token handling, or secret handling
  into the browser or into an AI-generated frontend.
- Keep access tokens in browser memory only. Refresh tokens stay in the
  restricted HttpOnly cookie managed by the API.
- Server-side middleware and resource policies are the authorization boundary.
  Frontend route guards are UX only.
- Do not disable CSRF, Origin checks, strict cookies, OAuth state validation,
  or backend authorization to make previews or tests easier.
- Do not commit `.env`, private signing keys, or user data.

## Project map

- Express API lives under `src/` (or `apps/api/src/` in fullstack).
- Shared Zod contracts live under `packages/contracts` (fullstack).
- Typed browser client lives under `packages/api-client` (fullstack).
- The fullstack frontend lives under `apps/web`: the tested React reference
  app, or a Next.js App Router starter when `--frontend next` was selected.
  Both call the same API through the typed `@authenik8/api-client`.
- Prisma schema and migrations live under `prisma/`.

## Common tasks

- Add a protected route: register it behind the auth middleware and add a
  resource policy; update OpenAPI and the typed client.
- Add a role: extend RBAC definitions, seed data, and tests.
- Add an OAuth provider: use the Identity Engine flow; normalize profile data;
  never create duplicate identities.
- Rotate signing keys: use the documented ops commands; never edit keys by hand.

## Validation

- Run `npm test` and `npm run typecheck`.
- Run `npx create-authenik8-app doctor --offline --strict` in CI.
- Keep generated React mode and Lovable mode correct when changing templates.

## AI editor tips

- Prefer editing server-side code for security-sensitive behavior.
- When generating UI, call the typed client instead of raw fetch.
- Keep changes small and focused; one concern per pull request.
