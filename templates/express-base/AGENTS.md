# AGENTS.md

## Project

This project was generated by `create-authenik8-app` (base preset). It is a
TypeScript Express API backed by the Authenik8 Identity Engine
(`authenik8-core`), Prisma, and PostgreSQL.

The generated `authenik8.json` manifest records the preset, generator version,
identity-engine version, runtime, database, and Prisma capability. It is the
source-controlled project contract: treat changes as migrations, and never add
secrets or deployment credentials to it.

## Commands

```bash
npm run dev          # start the development server
npm run build        # typecheck and build
npm run start        # start the built server
npm run db:migrate   # apply Prisma migrations
npm run prisma:migrate
npm run docker:up    # start local PostgreSQL
npm run docker:down  # stop local services
```

## Security invariants — never weaken these

- Authenik8 (the engine and this API) is the only identity and authorization
  authority. Do not add a second identity backend, a second users table, or a
  second sessions table.
- Do not disable CSRF, Origin checks, strict cookies, OAuth state, or backend
  authorization to make a preview or client easier.
- Access tokens live in memory only. Refresh tokens stay in sealed HttpOnly
  cookies. Never log cookies, tokens, or authorization headers.
- Do not put secrets in client-visible configuration or URLs.
- UI role checks are never authorization; enforce roles and policies in API
  middleware.
- Parse untrusted input with Zod. Return explicit errors, never stack traces
  or internal state.
- Keep the fail-closed behavior documented in `THREAT_MODEL.md` and the
  identity rules in `AGENT_IDENTITY.md`.

## Change discipline

- Make narrow changes; run `npm run build` and the project tests after any
  change.
- Do not change the manifest (`authenik8.json`) casually.
- Do not weaken a security test to land a feature; add a regression test with
  every security-relevant fix.
- Do not patch only example apps and claim the generator is fixed.
