# AGENTS.md

## Project

This project was generated by `create-authenik8-app` (fullstack preset). It is
a connected React and Express monorepo backed by the Authenik8 Identity Engine
(`authenik8-core`), Prisma, PostgreSQL, and Redis:

```text
apps/web    React frontend (the included reference app)
apps/api    Express API (identity, sessions, OAuth, account, projects, admin, audit)
packages/contracts   shared Zod contracts
packages/api-client  generated browser API client (@authenik8/api-client)
packages/ui          shared UI components
```

The generated `authenik8.json` manifest records the preset, generator version,
identity-engine version, package manager, runtime, database, Prisma
capability, OAuth providers, and frontend mode. It is the source-controlled
project contract: treat changes as migrations, and never add secrets or
deployment credentials to it.


## Runtime architecture

```text
React frontend (apps/web or a Lovable frontend)
        │  Standard HTTPS
        ▼
Authenik8 Express API (apps/api)
        │
   +----+----+
   ▼         ▼
PostgreSQL  Redis
```

Authenik8 remains authoritative for users, identities, password hashing, OAuth
state and callbacks, account linking, access-token verification, refresh-token
rotation, session state and revocation, CSRF, CORS and Origin policy, roles,
permissions, administrator authorization, audit events, business-resource
policies, PostgreSQL, and Redis data.

## Browser client rules

- Use `@authenik8/api-client` (`createAuthenik8Client`) from
  `packages/api-client`; do not rewrite it and do not fork it.
- Access tokens stay in memory. Refresh tokens stay in sealed HttpOnly
  cookies. Never persist tokens in localStorage, sessionStorage, IndexedDB,
  cookies, logs, analytics, or URLs.
- Use `credentials: "include"`, the CSRF bootstrap, and the client's retry
  and cross-tab coordination. Never disable CSRF.
- Exact browser Origin; no wildcard credentialed CORS.
- UI route guards are convenience, not authorization. Enforce roles and
  policies in API middleware.
- Logout and password changes revoke sessions server-side.

## API change discipline

Any API change must update, in order: route implementation, Zod/shared
contract, service/controller, OpenAPI, the committed static OpenAPI artifact,
the generated client (`npm run openapi:generate` + package build), the React
reference app, tests. Do not edit OpenAPI independently from routes.

## Security invariants — never weaken these

- Authenik8 (the engine and this API) is the only identity and authorization
  authority. Do not add a second identity backend, a second users table, or a
  second sessions table.
- Access tokens are limited to 24 hours and verified against the stateful
  Redis session: revocations and quarantine take effect immediately. Do not
  switch to stateless-only verification unless you have an explicit,
  documented online revocation boundary.
- Refresh rotation uses a per-session lock and atomic compare-and-set. Replay
  of a refresh token revokes the whole refresh family. Never disable rotation.
- Do not disable CSRF, Origin checks, strict cookies, OAuth state, or backend
  authorization to make a preview or client easier.
- Do not put secrets in client-visible configuration (`VITE_*`), URLs, or
  logs. Never log cookies, tokens, or authorization headers.
- Parse untrusted input with Zod. Return explicit errors, never stack traces
  or internal state.
- Keep the fail-closed behavior documented in `THREAT_MODEL.md`, the identity
  rules in `AGENT_IDENTITY.md`, and the preset contract in
  `PRESET_CONTRACT.md`.

## Lovable mode

If this project was generated with `--frontend lovable`, the
`integrations/lovable/` pack and the `.agents/skills/authenik8-lovable/`
skill define the frontend workflow. Lovable provides visual design, pages,
components, forms, and calls through the exported Authenik8 client. Lovable
must never enable Lovable Cloud auth or Supabase auth, create users/sessions
tables, implement OAuth callbacks, store tokens, use route guards as
authorization, recreate API routes in edge functions, or receive backend
secrets through `VITE_*` variables.

Run `npm run doctor:lovable` and `npm run openapi:check` before release
review. A `*.lovable.app` preview is for visual work only; test the complete
session lifecycle on a same-site custom domain.

## Change discipline

- Make narrow changes; run `npm run build:packages`, `npm run typecheck`, and
  `npm run test` after any change.
- Do not change the manifest (`authenik8.json`) casually.
- Do not weaken a security test to land a feature; add a regression test with
  every security-relevant fix.
- Do not patch only example apps and claim the generator is fixed.
