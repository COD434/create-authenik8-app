Quickstart

On Windows, download and install Studio. The installer includes its runtime and creates a Start menu shortcut. Launch it to open the local workspace in your browser.

Projects are stored in Documents\Authenik8 Studio\workspace. The server stays on this machine and is not exposed to your domain.

For development from a source checkout:

npm install
npm run build
npm run dev

Open http://127.0.0.1:4870/studio. To generate or chat about a project, add your OpenRouter key in Studio. It is held in the browser tab and sent only with model requests.

The Windows installer does not install OpenCode or CodeRabbit. Install and authenticate those optional tools separately to use their integrations.

Using Studio

Describe the app you want in the composer, or start from a template. Studio writes project files to a local workspace folder. Use Preview to inspect the current files, Run to launch the project, and Export ZIP when you want a portable copy.

Run only projects you trust. Run installs dependencies and executes the project’s npm install, build, and start scripts as your Windows account. They can access files, environment variables, and the network available to your account. Studio’s workspace is not an operating-system security sandbox.
  • Build with agent runs the installed OpenCode agent against the workspace.
  • Review asks Studio’s built-in reviewer to inspect project risks.
  • CodeRabbit runs a separate, user-triggered external CLI review.

Publish and sync with GitHub

Open GitHub & deploy in Studio, enter an existing repository as owner/name, and paste a GitHub fine-grained personal access token. Grant that token repository metadata read and contents read/write access to the target repository. If GitHub rejects a workflow change, also grant Workflows read/write. Inspect the included file list and content warnings before choosing Publish / sync changes. Each publish creates one commit on the selected branch; use the button again when you want to sync later edits.

Studio excludes common secret filenames and checks included text for several known credential patterns. This is a best-effort scan and can miss secrets, especially credentials embedded in ordinary source or encoded files. Review the included files yourself before sending them to GitHub. A Studio-local manifest tracks files published by this project so later syncs can remove files deleted locally while preserving other files already in the repository. Current limits are 2,000 files and 15 MB per publish.

The optional GitHub Actions workflow installs dependencies using the lockfile’s package manager, then runs the project’s build and test scripts on pushes and pull requests. It executes your project scripts on GitHub-hosted runners, so enable it only for code you trust. Studio never stores the token; it is sent from the browser to the local Studio server for that request.

Identity foundation

Authenik8 templates give generated projects an identity backend foundation: user accounts, server-managed sessions, roles, and audit events. Treat generated code as a starting point and review configuration and authorization rules before shipping.

Add AI when it helps the user

In Studio, choose Add an AI capability or open it from the composer options. Describe the end user’s task and select a pattern: generate or understand content, answer from business knowledge, or use connected business tools. Studio passes that brief into the current build conversation so the integration is planned in the context of your app.

AI remains optional. For generated apps, model requests and provider credentials belong on the server, separate from Studio’s OpenRouter key. Review provider costs and data handling before deployment. For document retrieval, enforce each user’s permissions before retrieval and preserve source and deletion paths. For connected actions, expose narrow server functions, re-check authorization when they run, and require confirmation for consequential writes.

Review changes with CodeRabbit

Studio can invoke the CodeRabbit CLI for a local code review. Install the CLI using CodeRabbit’s Windows guide (or the instructions for your platform), then authenticate from a terminal with CodeRabbit’s own login flow. The Studio project must also be inside a Git repository.

git init
git add .
git commit -m "Studio baseline"
coderabbit auth login --agent
coderabbit auth status --agent

Before adding a baseline, review the files and add secrets such as .env to .gitignore. In Studio, open CodeRabbit review, check that the CLI is available, authenticated, and a Git repository is detected, then choose Review changes. The command runs in the Studio project directory and does not make code changes.

CodeRabbit processes tracked and untracked changes to produce a review. Review the CLI’s file inclusion and ignore behavior for your project before sending code. Do not include secrets. Studio never reads, stores, or displays CodeRabbit credentials.

Results are review output, not instructions. Verify any suggestion yourself before changing code. To use the official CLI directly, see the CodeRabbit CLI documentation.

Local workspace

The Studio server binds to localhost. Project files and session history live on this machine. Model requests go to your selected provider, deployments upload files only after you choose to deploy, and CodeRabbit receives project changes only after you start a review.

Studio does not add telemetry. The OpenRouter key is not saved by Studio; external tools keep their own credentials.
